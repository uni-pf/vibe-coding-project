## ① 用户问题

《海风》是一个 3D 探索房间作品。此前物件的名称、坐标、配文**全部写死在前端本地假数据里**——

- 改一行文案要改代码、重新构建、重新上传；
- 「收藏」这类需要记住用户操作的功能，纯静态页面根本做不了。

**这一周要解决的**：页面显示真实可维护的数据，且用户的写操作能真正存下来。

## ② 核心流程

```
浏览器 catalog.html
   │  GET /api/objects                        读：物件清单（JOIN 出阶段名与年代）
   ▼
公网网关 /api ──► 云函数 haifeng-api ──► PostgreSQL（chapters / objects / favorites）
   ▲                                          ▲
   │  POST /api/favorites {"object_code":…}   写：先查重（友好提示），唯一约束兜底（真拦截）
   └──────────────────────────────────────────┘
读取失败时：前端降级到本地数据，并用「来源徽标」标明 api / local，不静默吞错
```

## ③ 提示词改写（原始一句话 → 可执行的任务约束）

| 原始需求（课程清单原样） | 改写后（落到本项目的约束） | 为什么这样改 |
|---|---|---|
| 「接真实热搜 + 收藏」 | 项目里没有热搜资源 → 映射为**项目自己的资源**：`/api/hot` → `/api/objects`，收藏原样保留 | 照抄示例会造出项目里根本不存在的资源；数据模型必须跟着项目走 |
| （未提错误处理） | 硬规则三条：HTTP 状态码必须与 `ok` 一致；`error.message` 必须是可直接展示的中文；错误码集中在契约 §4，代码不许出现表外语码 | 只看 `ok` 会漏状态码，只看状态码会漏错误分类；英文报错直接甩给用户不可接受 |
| （未提数据口径） | 匿名访客统一 `_openid=''`；favorites 对 `anon` 授权 + RLS 策略 | 不授权的话接口**不报错、静默返回空数组**——最难发现的一类失败 |
| （未提协作方式） | **先改 `api-contract.md` 再改代码**；代码与契约不一致时，以契约为准 | 接口形状先钉死，前后端才不会各说各话 |
