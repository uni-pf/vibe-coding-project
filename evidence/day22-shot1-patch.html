DAY 22 · 板块 ① 改（PATCH）· 第 4 周

改一条数据，并且看得见它变了

测试对象 obj-02（摊开的笔记本）。同时改两个字段：一个文本字段、一个颜色字段。
下面的「改前 / 改后」均取自两次真实 GET /api/objects 的返回原文，不是手写的对照表。
https://example-d3gz7b0wea9b8bb2e-1500064837.ap-shanghai.app.tcloudbase.com/api

一、发出的请求

PATCH /api/objects/obj-02 Content-Type: application/json { "memory_caption": "Day 22 改后值 · 由 PATCH 写入", "color": "#FF8A5B" }

二、字段级前后对照（GET 返回原文）

三、这一步真正验证到的两件事

① 改动确实落库了，不是"接口说改了"

PATCH  → HTTP 200，返回改后的整条记录
GET    → 再查一次，值仍然是新的

若只信 PATCH 的响应，就分不清
"写进去了" 和 "写的时候 echo 回来了"。

② PATCH 是局部更新，不是整体替换

请求里没提到的字段（name / shape /
position / sort_order）全部保持原值，
另外 4 条记录一个字段都没动。

换成 PUT 并漏写字段，这些位置就会
被清空 —— 这正是选 PATCH 的理由。
